# 상품별 구매 예측 모델 v1: 학습 데이터 생성 결과

[v1 설계](product-purchase-v1-spec.md) 10장의 1단계 결과다. `events.csv` 전체로 조회 시점별·후보 상품별 학습 데이터를 만들었다. 코드는 `ml/product_purchase/`에 있고, 실행 방법은 [ml/README](../../ml/README.md)에 있다.

## 생성 기준

- 완전히 동일한 이벤트 행 460건(조회 94, 장바구니 추가 366)을 제거했다.
- 사용자별 조회를 시간순으로 따라가며, 같은 시각의 조회를 묶어 예측 시점 하나로 만든다.
- 예측 시점마다 그때까지 조회했고 아직 구매하지 않은 모든 상품을 후보로 한 행씩 만든다.
- 정답은 예측 시점 이후 같은 상품을 구매하면 1, 데이터 끝까지 구매가 없으면 0이다. 시간 제한은 두지 않는다.
- 같은 시각에 조회와 구매가 기록된 예측 시점은 제외하도록 했으며, 해당 시점은 0개였다.
- 샘플링하지 않았다. 불균형 처리는 학습 단계에서 train에만 적용한다.

## 피처 정의

| 컬럼 | 정의 |
| --- | --- |
| `view_count` | 예측 시점까지 해당 상품의 조회 수 |
| `view_share` | `view_count` / 사용자 전체 조회 수 |
| `seconds_since_first_view` | 해당 상품 첫 조회 후 경과 초 |
| `seconds_since_last_view` | 해당 상품 마지막 조회 후 경과 초 |
| `revisit_count` | 이미 본 상품을, 바로 앞 조회가 다른 상품일 때 다시 본 횟수. 같은 상품의 연속 조회는 세지 않음 |
| `user_total_views` | 사용자의 전체 조회 수 |
| `distinct_items_viewed` | 사용자가 조회한 서로 다른 상품 수(구매한 상품 포함) |
| `is_last_viewed` | 가장 최근 시각에 조회한 상품이면 1. 같은 시각에 여러 상품을 봤다면 모두 1 |

이 밖에 `visitorid`, `cutoff_timestamp`, `itemid`, `heavy_user`, `label` 컬럼을 함께 저장한다. `heavy_user`는 평가용 표시이며 모델 입력이 아니다.

같은 시각 조회의 순서는 원본 파일 순서를 따른다. 이 순서는 `revisit_count`에만 영향을 준다.

## 사용자 분리

사용자 단위로 train/valid/test를 70/15/15로 나눴다(seed 42). 과다 조회 여부와 구매 여부로 층을 나누고, 각 층을 조회 수 순으로 정렬해 20명씩 14/3/3명을 무작위 배정했다.

| 구간 | 사용자 | 구매 사용자 | 과다 조회 사용자 | 과다 조회 구매 사용자 |
| --- | ---: | ---: | ---: | ---: |
| train | 982,925 | 7,627 | 262 | 124 |
| valid | 210,627 | 1,634 | 56 | 26 |
| test | 210,627 | 1,635 | 57 | 27 |

과다 조회 사용자는 조회 100회 이상인 사용자다.

## 검증

`validate_training_rows.py`로 다음을 확인했고 모두 통과했다.

- 한 사용자의 행이 배정된 구간에만 있다.
- 사용자별 행 수가 `users.parquet`의 기록과 같다.
- 같은 시각에 구매가 있는 예측 시점이 없다.
- 조회 뒤 구매한 사용자는 모두 정답 1 행을 가진다.
- 구간마다 무작위 시점, 정답 1이 있는 시점, 과다 조회 사용자의 시점을 뽑아(총 2,099개 시점, 341,597행) 원본 이벤트에서 다시 계산한 후보 목록·피처·정답과 비교했다. 재계산은 생성 코드와 별도로 pandas로 구현했다.

## 학습 단계에서 주의할 점

각 구간에서 사용자 한 명이 행의 약 25%를 차지한다. 조회량 상위 사용자가 구간마다 한 명씩 배정됐기 때문이다. 행 단위 지표만 보면 valid·test 성능이 사실상 그 사용자에 대한 성능이 되므로, 과다 조회 사용자를 제외한 지표와 사용자 단위 지표를 함께 확인한다. train에는 사용자별 가중치나 행 수 상한 등의 처리가 필요하다.
