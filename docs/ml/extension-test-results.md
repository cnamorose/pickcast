# 확장 기능 test 평가 결과

사용자 맞춤 화면(단계 판단)과 판매자 대시보드를 RetailRocket test 데이터로 한 번 확인했다. 기준값은 valid에서 정했고([단계 판단 검증](stage-validation.md)), test 결과를 보고 기준값이나 모델을 다시 조정하지 않았다.

코드: `ml/product_purchase/evaluate_extension_test.py` (결과 파일이 이미 있으면 실행되지 않음)

```powershell
.\ml\.venv\Scripts\python.exe ml/product_purchase/evaluate_extension_test.py
```

결과 파일: `ml/data/product_purchase/models/extension_test_metrics.json`

## 요약

| 확인할 것 (기획서 검증 계획) | 결과 |
| --- | --- |
| 단계별 이후 실제 구매율 | 구경 중 2.42% < 살 마음 먹음 3.96% < 고민 중 6.74%. valid와 같은 순서 |
| 모델이 단순 규칙보다 나은가 | 일반 고객: 모델 62.60% > 가장 많이 본 상품 58.89% > 가장 최근에 본 상품 50.21%. 전체 고객 기준에서는 가장 많이 본 상품(32.61%)이 모델(31.69%)보다 약간 높음 |

## 1. 단계별 구매율

valid 검증과 같은 방법이다. 고객 한 명을 세션 하나로 보고, 조회 100회 이상 고객은 뺐다.

| 단계 | 비중 | 그 뒤 아무거나 구매 | 대상 상품 구매 | (valid 대상 상품 구매) |
| --- | ---: | ---: | ---: | ---: |
| 조회 3회 미만 | 71.4% | 0.72% | - | - |
| 구경 중 | 12.6% | 2.42% | - | - |
| 살 마음 먹음 | 9.8% | 3.96% | 3.50% | 3.54% |
| 고민 중 | 1.2% | 6.74% | **5.97%** | 5.38% |
| 떠나려는 중 | 5.0% | 9.20% | 3.69% | 2.81% |

기준선: 조회 3회 이상 시점에서 모델 1위 상품을 그대로 골랐을 때 구매율 2.84%

- **재현된 것**: 구경 중 < 살 마음 먹음 < 고민 중 순서와, 단계가 가리킨 상품이 모델 1위 상품보다 잘 맞는다는 점. 고민 중이 실제 구매로 가장 많이 이어진다는 valid의 해석이 test에서도 유지됐다.
- **재현되지 않은 것**: 떠나려는 중의 대상 상품 구매율(3.69%)이 valid(2.81%)와 달리 살 마음 먹음(3.50%)보다 약간 높다. "그 상품에서 멀어진다"는 판단은 test에서 뒷받침되지 않는다. 떠나려는 중은 비중이 5%이고 고객 수가 적어 구간에 따라 흔들리는 것으로 보이며, 찜·가격 알림 유도는 "다시 볼 기회를 주는 안내" 정도로 해석하는 것이 안전하다.

## 2. 단순 규칙과 1순위 정답률

후보가 2개 이상이고 산 후보가 있는 시점에서, 각 방법이 1순위로 고른 상품이 실제로 산 상품인 비율이다.

| 고객 | 시점 | 모델 | 가장 많이 본 상품 | 가장 최근에 본 상품 | 무작위 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전체 | 12,838 | 31.69% | **32.61%** | 27.66% | 12.31% |
| 일반 고객 (조회 100회 미만) | 4,561 | **62.60%** | 58.89% | 50.21% | 30.41% |

- 가장 많이 본 상품: 조회 수가 가장 많은 후보 (같으면 더 최근에 본 상품)
- 가장 최근에 본 상품: 마지막 조회 후 경과 시간이 가장 짧은 후보

**우리 서비스 고객에 해당하는 일반 고객에서는 모델이 두 규칙보다 낫다** (가장 많이 본 상품보다 +3.7%p, 가장 최근에 본 상품보다 +12.4%p). "마지막에 본 상품을 고르는 것"보다 확실히 낫다.

전체 고객 기준에서는 가장 많이 본 상품이 모델보다 0.9%p 높다. 전체 시점의 대부분이 조회 100회 이상 고객의 시점이라 그 고객들의 결과에 가깝다. 모델의 가장 중요한 피처가 조회 횟수(63%)라 두 방법이 비슷하게 나오는 것은 자연스럽다. 모델은 1순위 고르기뿐 아니라 보정된 확률(대시보드 합산, 단계 판단의 배수)을 주는 점이 규칙과 다르다.

## 3. 대시보드 90% 범위 적중률

test 기록을 시간순으로 재생해, 매시 정각마다 최근 30분 안에 조회한 고객으로 대시보드를 만들었다. 서비스의 "지금 쇼핑 중" 기준과 같다. 고객마다 그 시각의 가장 최근 조회 시점 하나만 쓰고, 상품별로 확률을 모아 90% 범위를 계산한 뒤 그 고객들의 실제 구매 수와 비교했다. 데이터 마지막 달(9월)은 이후 구매를 볼 기간이 짧아 뺐다.

- 정각 2,899회, 쇼핑 중 고객 121,784명(정각별 합)

| 대상 | (정각, 상품) 묶음 | 범위 안 | 범위보다 많이 삼 | 예상 구매 합 | 실제 구매 합 |
| --- | ---: | ---: | ---: | ---: | ---: |
| 전체 | 224,407 | 99.3% | 0.7% | 2,062.1 | 1,659 |
| 범위가 0~0이 아닌 경우 | 3,322 | 100.0% | 0.0% | 215.7 | 199 |

- **범위가 넓게 잡힌다.** 목표인 90%보다 높다. 확률이 작고 구매 수가 0, 1개 같은 정수라 범위가 한 칸만 넓어도 적중률이 크게 오른다. 범위 밖으로 나간 경우는 모두 "범위보다 많이 산" 쪽이었다.
- 대부분의 묶음은 범위가 0~0이고 실제도 0개라 전체 적중률은 저절로 높다. 범위가 열린 경우만 봐도 100%다.

## 4. 일반 고객의 확률 보정

모델 확률은 전체 고객 기준(조회 시점 가중)으로 보정했다. 행의 대부분을 조회가 많은 소수 고객이 차지해서, 전체로는 맞지만 일반 고객만 보면 높게 나온다. valid에서 먼저 확인했고 test에서도 같았다.

| 대상 | 예측 | 실제 |
| --- | ---: | ---: |
| valid 전체 고객 (시점 가중) | 0.915% | 0.903% |
| valid 일반 고객 행 | 1.029% | 0.900% |
| valid 대시보드 재생 | 예상 합 2,048 | 실제 합 1,425 (44% 높음) |
| test 대시보드 재생 | 예상 합 2,062 | 실제 합 1,659 (24% 높음) |

우리 서비스 고객은 모두 일반 고객 쪽이라 **대시보드의 예상 구매 수는 실제보다 높게 나올 수 있다.** 대시보드 숫자가 0.몇 개 단위라 화면에서 차이는 작다. 대시보드에만 보정 계수를 곱하는 방법도 있었지만, 확률 기준이 화면마다 달라지고 모델이 바뀔 때마다 다시 정해야 해서 택하지 않았다. 일반 고객 기준의 재보정은 체험 데이터로 모델을 다시 맞추는 배치 재학습 단계에서 다룬다.

## 한계

- 고객 한 명을 세션 하나로 봤다. RetailRocket 고객 기록은 며칠에 걸쳐 이어지기도 해 체험 세션보다 길다.
- 화면을 바꾸거나 대시보드를 보고 조치했을 때 실제로 더 사는지는 개입 기록이 없어 확인할 수 없다. 실제 적용에는 A/B 테스트가 필요하다.
- 떠나려는 중은 고객 수가 적어 구간마다 결과가 흔들린다.
