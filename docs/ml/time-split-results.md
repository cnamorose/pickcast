# 시간 분할 검증과 장바구니·상품 통계 피처 실험

판매자용으로 방향을 바꾸면서 두 가지를 확인했다.

1. **시간 분할 검증**: 지금 모델(조회 피처 8개)을 과거 기간으로 학습하고 미래 기간으로 평가하면 성능이 얼마나 되는가
2. **피처 실험**: 체험형 화면 때문에 빼 두었던 장바구니와, 상품 단위 통계를 넣으면 얼마나 나아지는가

모든 피처는 `events.csv` 하나로 계산했다. 상품 속성 파일(`item_properties`, `category_tree`)은 쓰지 않았다. 서비스 모델(v1·v2)과 그 학습 데이터는 바꾸지 않았다.

## 1. 데이터 분할

사용자 단위 랜덤 분할(v1) 대신 기간으로 나눴다. 기간은 UTC 기준이다.

| 구간 | 기간 | 쓰임 |
| --- | --- | --- |
| train | 2015-05-03 ~ 06-30 | 학습, 상품 통계 계산 |
| valid | 2015-07-01 ~ 07-31 | 모델·피처 선택, 확률 보정, 임계값 |
| test | 2015-08-01 ~ 09-18 | 모든 결정을 마친 뒤 한 번만 평가 |

모든 기록(조회·장바구니·구매)이 한 구간 안에 있는 사용자만 그 구간에 넣었다. 두 구간 이상에 걸친 사용자는 뺐다. 한 사용자가 학습과 평가에 함께 들어가지 않고, 정답("이후 구매")도 다른 구간의 기록을 보지 않는다.

| 구간 | 사용자 | 구매 사용자 | 조회 |
| --- | ---: | ---: | ---: |
| train | 571,684 | 4,199 | 1,024,168 |
| valid | 341,122 | 2,132 | 551,536 |
| test | 443,653 | 2,992 | 728,811 |
| 제외 | 47,720 (3.4%) | 1,573 | 359,703 |

제외한 사용자는 3.4%지만 구매의 약 26%를 차지한다. 여러 달에 걸쳐 오는 단골과 조회가 아주 많은 고객이 대부분이다. 서비스 대상인 일반 고객은 거의 남지만, **여러 달에 걸친 단골에게도 잘 맞는지는 이 검증으로 알 수 없다.**

학습 행은 v1의 42,657,643개에서 9,447,108개로 줄었다. 그래도 train 행의 77%는 조회 100회 이상 고객의 것이고 한 사람이 14.5%를 차지해, v1처럼 예측 시점 가중치(point)가 필요하다.

## 2. 지금 모델을 시간 분할로 다시 학습

v1과 같은 피처 8개, 같은 LightGBM 설정, 같은 보정 방식(isotonic_smooth)을 쓰고 분할만 바꿨다.

### valid로 모델 선택

| 모델 | 반복 | 시점 가중 AP | AUC | 일반 고객 AP | 과다 조회 고객 AP |
| --- | ---: | ---: | ---: | ---: | ---: |
| 단순 구매 비율 | - | 0.0079 | 0.500 | 0.0090 | 0.0051 |
| 로지스틱 회귀 | - | 0.0200 | 0.678 | 0.0222 | 0.0212 |
| LightGBM row | 233 | 0.0273 | 0.695 | 0.0299 | 0.0176 |
| **LightGBM point** | 53 | **0.0274** | **0.695** | 0.0295 | **0.0256** |
| LightGBM user | 54 | 0.0273 | 0.694 | 0.0293 | 0.0177 |

v1과 같은 기준으로 point를 골랐다. 보정은 isotonic_smooth, 임계값은 3.38%다.

### test: 사용자 단위 분할(v1)과 비교

각자의 test에서 잰 값이다.

| 지표 | 사용자 단위 분할 (v1) | 시간 분할 |
| --- | ---: | ---: |
| 시점 가중 AP (단순 기준 대비) | 0.0310 (3.4배) | 0.0268 (3.2배) |
| ROC-AUC | 0.700 | 0.693 |
| 일반 고객 AP (단순 기준 대비) | 0.0393 (3.9배) | 0.0332 (3.0배) |
| 반복 조회 시점 AUC | 0.734 | 0.728 |
| 정밀도 / 재현율 | 5.39% / 14.25% | 4.68% / 16.54% |
| 1순위 정답률, 일반 고객 | 62.60% | 56.80% |
| └ 가장 많이 본 상품 | 58.89% | 56.60% |
| 평균 예측 / 실제 | 0.92% / 0.92% | 0.78% / 0.85% |

- **구분력(AUC)은 미래 기간에도 거의 유지된다.**
- **일반 고객에서 가장 많이 떨어진다.** 특히 "가장 많이 본 상품"보다 낫다는 우위가 +3.7%p에서 +0.2%p로 거의 사라졌다. 사용자 단위 분할은 학습과 평가가 같은 기간이라 그 시기의 상품 인기를 이미 알고 있어 조금 유리했다.
- **보정은 기간이 바뀌면 어긋난다.** 7월에 맞춘 확률이 8월에 약 8% 낮게 나왔다(8월 예측 0.79%, 실제 0.88%).

v1의 성능은 사용자 단위 분할에서 약간 부풀려져 있었다. 아래 피처 실험은 시간 분할을 기준으로 비교한다.

## 3. 왜 조회만으로는 어려운가

원본 구매 21,270건을 보면 조회 기록만으로는 구매자와 비구매자가 잘 구분되지 않는다.

| 확인 | 비율 |
| --- | ---: |
| 산 상품을 사기 전에 딱 한 번 봤다 | 48.1% |
| 산 상품을 조회 없이 샀다 | 11.9% |
| 첫 구매 전에 본 상품이 1종류였다 | 52.3% |
| 방문자 중 상품 하나를 한 번 보고 떠났다 | 71.8% |
| **산 상품을 사기 전에 장바구니에 담았다** | **89.1%** |

"한 번 보고 산 사람"과 "한 번 보고 떠난 사람"은 조회 기록상 같다. 첫 조회 시점 AUC가 0.50인 이유다. 반면 구매의 89%가 장바구니를 거친다. v1은 체험 화면(결과 화면, AI와 대결)에서 장바구니가 정답을 거의 알려주므로 입력에서 뺐지만, 판매자용에서는 그 제약이 없다.

## 4. 피처 실험

### 추가한 피처

| 묶음 | 피처 | 계산 |
| --- | --- | --- |
| view (기존) | 조회 수, 조회 비중, 첫·마지막 조회 후 경과 시간, 재방문 수, 전체 조회 수, 본 상품 수, 가장 최근에 본 상품인지 | 조회한 상품은 기존과 같은 값. 담기만 한 상품은 경과 시간이 비어 있음 |
| cart | 상품을 담은 횟수, 마지막으로 담은 뒤 경과 시간, 고객이 담은 상품 수 | |
| item | 상품을 조회한 사람 수, 조회 대비 구매율, 조회 대비 담기율 | train 기간(5~6월) 기록만. 비율은 20명을 더 본 것처럼 전체 비율 쪽으로 당김. train 행은 사용자를 5묶음(visitorid % 5)으로 나눠 자기 묶음을 뺀 통계를 씀 |
| context | 시각, 요일, 방문 횟수, 이전 방문 이후 경과 시간, 이번 방문의 조회 수 | 30분 넘게 쉬면 새 방문 |
| history | 예측 시점 이전에 구매한 상품 수 | |

예측 시점에 **장바구니 담기**를 추가하고, **조회하지 않고 담은 상품**도 후보에 넣었다. 정답은 같다(예측 시점 이후 그 상품을 샀는가).

| 구간 | 행 | 정답 1 | 담기가 있는 예측 시점 |
| --- | ---: | ---: | ---: |
| train | 10,189,717 | 68,098 (0.668%) | 22,724 |
| valid | 2,471,833 | 22,180 (0.897%) | 10,942 |
| test | 5,040,264 | 46,502 (0.923%) | 16,720 |

### 실험 방법

8개 조합을 같은 행으로 학습하고 valid로 비교했다. 모델은 LightGBM point 가중치 하나로, 설정은 기존과 같다. 순위 지표라 보정 전 점수로 비교했다.

**구매 직전 1순위 정답률**은 이번에 추가한 지표다. 구매한 사용자마다 첫 구매 직전 예측 시점 하나만 보고, 모델이 1위로 꼽은 상품이 산 상품인지 센다. 그 시점에 방금 보거나 담은 상품이 산 상품이면 한 시점 앞을 본다. 결제하러 들어간 조회를 빼는 결과 화면·AI와 대결과 같은 규칙이다. 빼지 않으면 "가장 최근 본 상품"이 거의 항상 맞는다.

### 주의: 행 구성으로 장바구니 정보가 샌다

조회 피처만 쓴 조합(view)도 이 행에서는 AP가 0.141로 나온다. 담기만 한 상품은 조회 수가 0이고, 담기 시점에는 방금 담은 상품이 후보에 있어 조회 피처만으로도 장바구니를 짐작할 수 있기 때문이다.

그래서 **기존과 같은 행(조회 시점의 조회한 상품)만** 떼어 따로 비교했다. 이 행에서 view 조합의 AP는 0.027로, 2절 기준선(0.0274)과 같다.

| 조합 (valid, 조회 시점의 조회한 상품) | AP | AUC |
| --- | ---: | ---: |
| view | 0.027 | 0.695 |
| view + cart | 0.073 | 0.730 |
| 전체 | 0.088 | 0.809 |
| 전체 − cart | 0.041 | 0.776 |

기준 구매 비율은 0.78%다.

### 결과 (valid, 전체 행)

| 조합 | 반복 | 시점 가중 AP | AUC | 일반 고객 AP | 첫 조회 시점 AUC | 구매 직전 1순위 |
| --- | ---: | ---: | ---: | ---: | ---: | ---: |
| view | 57 | 0.141 | 0.782 | 0.109 | 0.693 | 71.35% |
| view + cart | 117 | 0.176 | 0.810 | 0.177 | 0.701 | 82.90% |
| **view + cart + item** | 54 | 0.193 | 0.861 | **0.189** | 0.832 | 81.31% |
| 전체 | 49 | **0.194** | **0.863** | 0.186 | **0.836** | 81.09% |
| 전체 − cart | 45 | 0.150 | 0.835 | 0.114 | 0.832 | 69.31% |
| 전체 − item | 76 | 0.181 | 0.830 | 0.173 | 0.758 | 82.90% |
| 전체 − context | 45 | 0.193 | 0.861 | 0.189 | 0.832 | 81.65% |
| 전체 − history | 51 | 0.193 | 0.863 | 0.182 | 0.835 | 81.20% |

구매 직전 1순위는 883명 기준이다. 같은 시점에서 가장 많이 본 상품은 70.44%, 가장 최근 본 상품은 69.42%, 무작위는 42.60%다.

- **cart가 가장 크다.** 빼면 AP가 0.194에서 0.150으로 가장 많이 떨어지고, 구매 직전 1순위는 단순 규칙보다 낮아진다.
- **item은 처음 본 상품을 구분하게 한다.** 첫 조회 시점 AUC가 0.69에서 0.83이 된다. 빼면 0.76으로 떨어진다. v1의 가장 큰 약점이던 부분이다.
- **context와 history는 효과가 거의 없다.** 빼도 AP 변화가 0.002 이하다.
- 구매 직전 1순위에서 1~2%p 차이는 883명 기준이라 구분하기 어렵다. cart를 넣고 뺄 때의 약 12%p 차이만 뚜렷하다.

### 최종 조합: view + cart + item

전체 조합과 시점 가중 AP 차이가 0.002로 작고, 서비스 대상인 일반 고객 AP는 더 높다(0.189 vs 0.186). 효과가 없는 context와 history를 빼 피처가 20개에서 14개로 줄었다.

피처 중요도(gain)는 다음과 같다.

| 피처 | 비중 |
| --- | ---: |
| 마지막으로 담은 뒤 경과 시간 | 62.3% |
| 상품의 담기율 | 12.2% |
| 조회 수 | 5.1% |
| 고객이 담은 상품 수 | 4.2% |
| 상품을 조회한 사람 수 | 3.8% |
| 상품의 구매율 | 3.5% |
| 첫 조회 후 경과 시간 | 3.1% |
| 나머지 7개 | 각 2% 이하 |

보정은 isotonic_smooth, 임계값은 14.36%로 valid에서 정했다. valid(교차 보정)에서 정밀도 24.73%, 재현율 41.46%다.

## 5. test 평가

최종 조합으로 test를 한 번 평가했다. 결과를 보고 다시 조정하지 않았다. 비교 대상은 2절의 시간 분할 기준선(조회 피처 8개)이다.

| 지표 | 조회 피처만 (2절) | view + cart + item |
| --- | ---: | ---: |
| 시점 가중 AP (단순 기준 대비) | 0.0268 (3.2배) | **0.1789 (14.6배)** |
| ROC-AUC | 0.693 | **0.815** |
| 일반 고객 AP (단순 기준 대비) | 0.0332 (3.0배) | **0.1748 (11.1배)** |
| 반복 조회 시점 AUC | 0.728 | **0.831** |
| 정밀도 / 재현율 | 4.68% / 16.54% | **24.10% / 40.01%** |
| 1순위 정답률, 일반 고객 | 56.80% | **69.81%** |
| └ 가장 많이 본 상품 | 56.60% | 57.73% |
| 구매 직전 1순위 (결제 조회 제외) | 60.26% (936명) | **75.43%** (1,266명) |
| └ 가장 많이 본 상품 | 55.98% | 68.64% |
| 사용자·상품 단위 AP | 0.037 | **0.339** |

두 열은 행 구성이 다르다(오른쪽은 담기 시점과 담기만 한 상품을 포함). 같은 행(조회 시점의 조회한 상품)만 보면 AP는 0.027에서 **0.079(2.9배)**, AUC는 0.693에서 0.739다.

## 6. 정리

- 조회 피처만 쓴 모델은 시간 분할에서 단순 기준의 3배 정도이고, "가장 많이 본 상품"과 거의 같았다. 조회 기록에 구매자와 비구매자를 나눌 정보가 적기 때문이다.
- 장바구니와 train 기간 상품 통계를 넣으면, 미래 고객 기준으로 **구매 직전 1순위 정답률 60% → 75%, 구매 판정 정밀도 5% → 24%, 재현율 17% → 40%**가 된다.
- 효과는 장바구니(특히 마지막으로 담은 뒤 경과 시간)가 가장 크고, 상품 통계가 처음 본 상품의 구분을 맡는다. 시각·방문·과거 구매는 거의 기여하지 않는다.

## 한계

- 두 구간 이상에 걸친 사용자(구매의 약 26%)를 뺐다. 여러 달에 걸친 단골에 대한 성능은 확인하지 않았다.
- 데이터가 9월 18일에 끝나, 9월 고객은 이후 구매가 덜 잡힌다.
- 장바구니에 담은 직후 예측이 대부분의 성능을 낸다. 조회만 하고 담지 않은 고객에 대해서는 여전히 약하다(같은 행 비교 AP 0.079).
- 상품 통계는 train 기간에 없던 신상품에 전체 평균을 준다.
- 서비스 모델(v2)에는 아직 반영하지 않았다. 반영하려면 예측 모듈과 백엔드가 장바구니 기록과 상품 통계를 받아야 한다.

## 실행 방법

결과는 `ml/data/product_purchase_time/`에 생긴다. 프로젝트 최상위 폴더에서 실행한다.

```powershell
$env:PRODUCT_PURCHASE_DIR = "product_purchase_time"
$env:PYTHONIOENCODING = "utf-8"

# 2절: 시간 분할, 조회 피처 8개
.\ml\.venv\Scripts\python.exe ml/product_purchase/split_by_time.py
.\ml\.venv\Scripts\python.exe ml/product_purchase/build_training_rows.py
.\ml\.venv\Scripts\python.exe ml/product_purchase/validate_training_rows.py
.\ml\.venv\Scripts\python.exe ml/product_purchase/train_models.py
.\ml\.venv\Scripts\python.exe ml/product_purchase/calibrate_model.py --model lgbm_point
.\ml\.venv\Scripts\python.exe ml/product_purchase/evaluate_time_split.py

# 4·5절: 피처 실험 (split_by_time.py 결과를 그대로 씀)
.\ml\.venv\Scripts\python.exe ml/product_purchase/build_extended_rows.py
.\ml\.venv\Scripts\python.exe ml/product_purchase/run_feature_experiments.py
.\ml\.venv\Scripts\python.exe ml/product_purchase/calibrate_model.py --experiment view_cart_item
.\ml\.venv\Scripts\python.exe ml/product_purchase/evaluate_time_split.py --experiment view_cart_item
```

| 결과 파일 (`ml/data/product_purchase_time/`) | 내용 |
| --- | --- |
| `split_report.json` | 구간별 사용자 수 |
| `models/validation_metrics.json`, `calibration.json`, `test_metrics.json` | 2절 |
| `extended_rows/build_report.json` | 확장 학습 데이터 |
| `feature_experiments/valid_metrics.json` | 피처 실험 8개의 valid 결과 |
| `feature_experiments/view_cart_item/calibration.json`, `test_metrics.json` | 최종 조합의 보정과 test |

`evaluate_time_split.py`는 `test_metrics.json`이 이미 있으면 실행되지 않는다. 학습 데이터 생성은 각각 5분 안팎, 피처 실험 8개는 약 20분이 걸린다.
