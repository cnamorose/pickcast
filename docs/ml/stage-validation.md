# 구매 의도 단계 판단: valid 검증 결과

사용자 맞춤 화면의 단계 판단(`ml/product_purchase/stage.py`의 `judge_stage`)이 실제 구매와 연결되는지 RetailRocket valid 데이터로 확인했다. 기준값은 손으로 만든 조회 흐름으로 정한 임시값이었고, 이번 검증으로 **기준값은 그대로 두고 단계의 해석을 바로잡았다.** test는 쓰지 않았다.

코드: `ml/product_purchase/validate_stage.py`

```powershell
.\ml\.venv\Scripts\python.exe ml/product_purchase/validate_stage.py          # 지금 기준값 (약 15초)
.\ml\.venv\Scripts\python.exe ml/product_purchase/validate_stage.py --grid   # 기준값 108개 조합 비교 (약 11분)
```

## 방법

1. valid 학습 행(조회 시점 × 후보 상품)에 서비스와 같은 모델·보정으로 확률을 붙였다.
2. 고객별로 묶어 `predictor.timeline()`과 같은 형태로 다시 만들고, 조회 시점마다 `judge_stage`를 돌렸다.
3. 각 시점에서 그 뒤 실제 구매 여부(학습 행의 정답)를 단계별로 모았다.
   - **아무거나 구매**: 그 시점의 후보 중 하나라도 샀는가. 단계가 구매 의도를 나누는지 본다.
   - **대상 상품 구매**: 단계가 가리킨 상품(`items`) 중 하나를 샀는가. 비교 카드나 강조할 상품을 제대로 골랐는지 본다.

- RetailRocket에는 세션이 없어 **고객 한 명을 세션 하나로** 봤다. 서비스도 체험 한 번이 세션 하나다.
- 조회 100회 이상 고객은 뺐다. 상위 100명이 행의 84%를 차지하고, 조회 몇~수십 번인 체험 세션과 성격이 다르다.
- 대상: 고객 210,560명, 조회 시점 378,204개

## 결과

| 단계 | 시점 | 비중 | 그 뒤 아무거나 구매 | 대상 상품 구매 |
| --- | ---: | ---: | ---: | ---: |
| 조회 3회 미만 (판단 안 함) | 269,908 | 71.4% | 0.73% | - |
| 구경 중 | 47,796 | 12.6% | 2.28% | - |
| 살 마음 먹음 | 37,302 | 9.9% | 4.02% | 3.54% |
| 고민 중 | 4,776 | 1.3% | **6.70%** | **5.38%** |
| 떠나려는 중 | 18,422 | 4.9% | 8.79% | 2.81% |
| 조회 3회 이상 전체 | 108,296 | | 4.18% | |

기준선: 조회 3회 이상 시점에서 **모델 1위 상품을 그대로 골랐을 때** 그 상품을 산 비율은 2.63%다.

### 맞는 것

- **단계가 구매 가능성을 나눈다.** 조회 3회 미만 0.73% → 구경 중 2.28% → 살 마음 먹음 4.02% → 고민 중 6.70%로, 최대 9배 차이가 난다.
- **단계가 가리킨 상품은 모델 1위 상품보다 잘 맞는다.** 고민 중 5.38%, 살 마음 먹음 3.54%로 기준선 2.63%보다 높다.
- **떠나려는 중의 대상 상품은 덜 산다** (2.81%, 살 마음 먹음 3.54%보다 낮음). 그 상품에서 멀어진다는 판단은 맞다. 반면 아무거나 구매는 8.79%로 가장 높아, 다른 상품으로 옮겨 가서 사는 고객이 많다.

### 예상과 다른 것

**고민 중 고객이 살 마음 먹음 고객보다 더 많이 산다** (대상 상품 5.38% vs 3.54%). 같은 상품만 반복해서 본 고객보다, 두세 상품을 여러 번씩 오가며 비교한 고객이 실제 구매로 더 많이 이어진다. 기획서는 "살 마음 먹음"을 가장 높은 구매 의도로 가정했지만 데이터는 그렇지 않다.

## 기준값을 바꿔 본 결과

### 기준값 조합 (108개)

`decided_lift`(1.5~3.0), `decided_ratio`(1.5~2.0), `decided_share`(0.4~0.6), `comparing_lift`(1.5~2.0)를 바꿔 봤다.

- 살 마음 먹음의 대상 상품 구매율은 **3.54%~3.82%** 안에서만 움직였다. 판정 비중은 7.7%~9.9%다.
- 가장 높은 조합(`decided_lift` 3.0, `decided_ratio` 2.0, `decided_share` 0.4)도 지금보다 0.3%p 높을 뿐이다. 이 조합은 lift 3배가 필요해, 빠르게 클릭하는 체험 세션(1~5초 간격이면 반복 조회해도 약 2.5배)에서는 살 마음 먹음이 나오지 않는다.
- 어떤 조합에서도 고민 중이 살 마음 먹음보다 높았다.

### 판단 대상 상품의 최소 조회 수

| 최소 조회 수 | 고민 중 비중 / 대상 구매 | 살 마음 먹음 비중 / 대상 구매 | 떠나려는 중 비중 / 대상 구매 |
| --- | --- | --- | --- |
| 2회 (현재) | 1.3% / 5.38% | 9.9% / 3.54% | 4.9% / 2.81% |
| 3회 | 0.5% / 6.79% | 6.1% / 4.31% | 2.4% / 2.42% |
| 4회 | 0.3% / 10.41% | 3.2% / 4.77% | 1.5% / 2.51% |

기준을 높이면 구매율은 오르지만 판정이 크게 줄어, 3회부터는 고민 중이 시점의 0.5%에서만 나온다. 체험에서 거의 볼 수 없게 되고, 고민 중 > 살 마음 먹음 순서도 그대로다.

## 결정

**기준값은 바꾸지 않는다.** 바꿔서 얻는 구매율 차이가 작고, 빠르게 클릭하는 체험 세션에서 단계가 나오는 것이 더 중요하다. 고민 중과 살 마음 먹음의 순서는 기준값이 아니라 단계 정의의 문제라 숫자 조정으로 바뀌지 않는다.

**해석을 바로잡는다.**

| 단계 | 기존 해석 | 검증 후 해석 |
| --- | --- | --- |
| 살 마음 먹음 (`decided`) | 가장 높은 구매 의도 | 한 상품에 관심이 집중된 상태. 구경 중보다 많이 사지만 고민 중보다는 적게 산다 |
| 고민 중 (`comparing`) | 망설이는 상태 | **실제 구매로 가장 많이 이어지는 상태** |
| 떠나려는 중 (`leaving`) | 이탈 직전 | 그 상품에서는 멀어지지만, 다른 상품을 사는 경우가 많다 |

- API 값과 화면 대응은 그대로 쓴다. 살 마음 먹음에서 팝업을 끄고 구매 버튼을 강조해도 해가 없다.
- 고민 중 고객이 가장 많이 사므로, **비교 모달이 가장 효과를 기대할 만한 화면 대응**이다. 다만 화면을 바꿨을 때 실제로 더 사는지는 개입 기록이 없어 확인할 수 없다 (A/B 테스트 필요).

## 이후 변경: `decided_ratio` 1.8 → 1.7

모델 v2([일반 고객 기준 재보정](recalibration-v2.md))로 바꾸자 A B A A A를 20초 간격으로 본 흐름에서 1위가 2위의 1.77배로 기준(1.8)에 못 미쳐 구경 중이 됐다. 보정은 순서를 지키지만 확률 사이의 비율은 조금 바꾸기 때문이다. 기준을 1.7로 낮췄고, valid 결과는 거의 같다.

| 모델 / 기준 | 살 마음 먹음 비중 | 아무거나 구매 | 대상 상품 구매 |
| --- | ---: | ---: | ---: |
| v1 / 1.8 (위 결과) | 9.9% | 4.02% | 3.54% |
| v1 / 1.7 | 10.1% | 4.02% | 3.52% |
| v2 / 1.8 | 9.5% | 4.08% | 3.62% |
| v2 / 1.7 | 9.6% | 4.06% | 3.60% |

다른 단계는 기준 변경의 영향을 받지 않는다. 단계 시나리오 테스트(`tests/test_stage.py`)는 이제 등록된 모든 모델 버전으로 확인한다.

## 한계

- 고객 한 명을 세션 하나로 봤다. RetailRocket 고객 기록은 며칠에 걸쳐 이어지기도 해 체험 세션보다 길다.
- 단계 판단은 모델 확률 위의 규칙이라 모델의 구분력(반복 조회 시점 AUC 0.734)을 넘지 못한다. 가장 높은 고민 중도 100명 중 약 7명만 산다.
- 기준값은 valid에서 정했다. test 확인은 기준선 비교, 90% 범위 적중률과 함께 따로 한다.
