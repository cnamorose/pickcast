# 첫 모델의 학습 데이터 생성 기준

## 예측 목표

예측 시점까지의 조회 행동으로,
후보 상품 각각의 이후 30분 내 구매 여부를 예측한다.

30분은 첫 실험의 관찰 기간이며, 이후 비교 실험으로 조정할 수 있다.

## 데이터 사용

- RetailRocket의 events.csv만 사용한다.
- view는 입력 피처 계산에 사용한다.
- transaction은 정답 생성에만 사용한다.
- addtocart는 모델 입력과 세션 구분에 사용하지 않는다.
- 완전히 동일한 행도 현재 단계에서는 삭제하지 않는다.

## 세션 구분

- 사용자별 조회 기록을 시간순으로 정렬한다.
- 직전 조회와의 간격이 30분 이상이면 새 세션으로 구분한다.
- 세션 구분의 30분과 구매 확인 기간의 30분은 별개의 기준이다.

## 예측 시점과 후보

- 각 조회 발생 시점에서 학습 예제를 만든다.
- 같은 사용자의 같은 시각에 발생한 조회는 함께 반영한 뒤
  예제를 한 번만 만든다.
- 현재 세션에서 예측 시점까지 발생한 조회만 입력에 사용한다.
- 후보는 해당 시점까지 조회한 서로 다른 모든 상품이다.
- 구매 결과를 보고 예측 시점을 고르지 않는다.
- 구매·장바구니 기록이 있다는 이유로 후보 상품을 제외하지 않는다.
- 후보가 한 개인 예제도 유지한다.
- 여러 후보 중 상품을 고르는 성능은 후보가 두 개 이상인
  예제를 별도로 평가한다.

## 첫 모델의 입력 피처

- view_count: 해당 상품의 조회 횟수
- view_share: 전체 조회 중 해당 상품의 조회 비율
- seconds_since_first_view: 해당 상품의 첫 조회 후 경과 시간
- seconds_since_last_view: 해당 상품의 마지막 조회 후 경과 시간

반복 조회는 조회 횟수에 반영한다.
다른 상품을 보고 돌아오는 패턴과 조회 순서는 이후 추가 실험한다.
경과 시간은 실제 체류 시간을 의미하지 않는다.
이전 세션의 행동은 현재 입력에 포함하지 않는다.

visitorid, session_id, 예측 시각, itemid는 기록 연결·평가용으로
보관하며 첫 모델의 입력 피처에서는 제외한다.

## 구매 정답

- 같은 사용자의 예측 시점 이후부터 30분 이내 구매를 확인한다.
- 구매한 후보 상품은 label=1, 구매 기록이 없는 후보는 label=0이다.
- 여러 후보를 구매했다면 각각 모두 1로 표시한다.
- 구매가 없는 예제도 모든 후보를 0으로 표시하여 유지한다.
- 예측 이후 조회는 해당 예제의 입력이나 후보에 추가하지 않는다.
- 예측과 정확히 같은 시각에 구매가 있으면 해당 예제를 제외하고
  제외 개수를 기록한다.
- 데이터 종료 때문에 이후 30분을 관찰할 수 없는 예제는 제외한다.

label=0은 관찰 기간 안에 구매 기록이 없다는 의미이다.

## 데이터 분리 및 평가

- 시간순으로 학습·검증·평가 구간을 분리한다.
- 같은 세션의 예제를 서로 다른 구간에 섞지 않는다.
- 학습 예제의 구매 확인 기간이 검증 구간을 침범하지 않도록 한다.
- 경계에서 제외하는 세션과 예제의 개수를 기록한다.
- 공개 데이터의 실제 구매 예측과 웹 체험의 최종 선택 예측은
  평가 결과를 구분한다.
