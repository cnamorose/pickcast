# 모델 v2: 일반 고객 기준 재보정

[확장 기능 test 평가](extension-test-results.md)에서 v1 확률이 일반 고객(조회 100회 미만)에게 실제보다 높게 나오는 것을 확인했다. 서비스 고객은 모두 일반 고객 쪽이라, 모델은 그대로 두고 보정만 일반 고객 기준으로 다시 맞춰 v2를 만들었다. 배치 재학습 파이프라인의 "학습 → 평가 → 기준을 통과하면 등록"을 처음으로 한 바퀴 돈 사례다.

코드: `ml/product_purchase/recalibrate.py` (v2 폴더가 이미 있으면 실행되지 않음)

```powershell
.\ml\.venv\Scripts\python.exe ml/product_purchase/recalibrate.py
```

결과 파일: `ml/data/product_purchase/recalibration_v2.json`

## 방법

- **모델**: v1의 LightGBM(`lgbm_point.txt`)을 그대로 쓴다. 보정은 순서를 바꾸지 않아 AUC·AP, 1순위 정답률, 단계 순서는 그대로다.
- **데이터**: valid 일반 고객(916,198행)을 고객 단위로 반반 나눴다. A(456,182행)로 보정하고, B(460,016행)로 v1과 비교했다. test는 쓰지 않았다.
- **보정**: v1과 같은 `isotonic_smooth`. 가중치는 v1(조회 시점마다 합 1)과 달리 후보 상품 하나하나를 같은 무게로 뒀다. 대시보드는 후보 상품별 확률을 더해 예상 구매 수를 내므로 상품 하나하나의 확률이 맞아야 합계가 맞는다.
- **임계값**: v1처럼 A를 고객 단위 5묶음으로 나눈 교차 보정 확률에서 F1이 가장 높은 값으로 정했다.

## 단계 판단에 주는 영향 (B)

| 단계 | 비중 v1 → v2 | 그 뒤 아무거나 구매 v1 → v2 | 대상 상품 구매 v1 → v2 |
| --- | --- | --- | --- |
| 구경 중 | 12.9% → 13.3% | 2.18% → 2.25% | - |
| 고민 중 | 1.3% → 1.2% | 6.65% → 6.60% | 5.15% → 5.07% |
| 살 마음 먹음 | 9.9% → 9.6% | 4.06% → 4.08% | 3.61% → 3.65% |
| 떠나려는 중 | 4.9% → 4.9% | 8.41% → 8.34% | 2.87% → 2.87% |

단계는 기준 확률 대비 배수로 판단하고 기준 확률도 v2로 함께 바뀌어, 비중과 구매율이 거의 같다 (위 표는 당시 기준값 `decided_ratio` 1.8).

다만 개별 흐름 하나가 기준 경계에서 바뀌었다. A B A A A를 20초 간격으로 보면 v1에서는 1위가 2위의 1.97배였지만 v2에서는 1.77배로 기준 1.8에 못 미쳐 살 마음 먹음이 아니라 구경 중이 됐다. 보정은 순서를 지키지만 확률 사이의 비율은 조금 바꾸기 때문이다. `decided_ratio`를 1.7로 낮춰 v1·v2 모두에서 대표 흐름이 의도한 단계가 되게 했다. valid 단계별 구매율은 거의 같다 ([단계 판단 검증](stage-validation.md)의 "이후 변경").

## 남은 차이

v2도 일반 고객에게 조금 높고, 대시보드 재생에서는 40% 높다. 원인을 나눠 보면 다음과 같다.

| 확인 | 예측 | 실제 | 차이 |
| --- | ---: | ---: | ---: |
| A 전체 행 (보정에 쓴 고객) | 0.928% | 0.930% | 거의 없음 |
| B 전체 행 | 0.938% | 0.871% | +8% |
| A로 대시보드 재생 | 예상 합 926.7 | 실제 합 754 | +23% |

- **행 단위 보정은 맞다.** 보정에 쓴 A에서 예측과 실제가 같다. B에서 8% 높은 것은 B의 실제 구매율이 A보다 낮기 때문이다. 구매가 소수 고객에게 몰려 있어 고객을 반으로 나누면 구매율이 이 정도 흔들린다.
- **대시보드 표본은 구조적으로 높게 나온다.** 보정에 쓴 A로 재생해도 23% 높다. 보정은 모든 조회 시점의 모든 후보 행을 같은 무게로 맞추는데, 대시보드는 매시 고객마다 가장 최근 조회 시점 하나만 쓴다. 두 표본의 구성이 달라 대시보드 표본에서는 확률이 높게 나온다.
- 대시보드 표본과 같은 방식(고객별 최근 조회 시점)으로 가중치를 두고 보정하면 줄일 수 있다. 다음 재보정(v3) 후보로 남긴다.

```powershell

```

## 한계

- valid만 사용했다. test는 확장 기능 평가에서 이미 한 번 썼다.
