# 상품별 구매 예측 모델 v1 설계

## 1. 목표

사용자의 조회 행동이 쌓일 때마다, 사용자가 본 **각 상품의 구매 예측 확률**을 갱신한다.

예측 단위는 `(사용자, 상품, 예측 시점)`이다. 사용자 전체의 구매 확률 하나를 예측하거나, 여러 상품 중 하나만 고르는 모델이 아니다.

- 각 상품에 대해 구매 확률과 `구매 예상` 또는 `미구매 예상`을 출력한다.
- 여러 상품을 모두 구매 예상으로 판정할 수 있고, 전부 미구매 예상으로 판정할 수도 있다.
- 상품별 확률의 합은 100%일 필요가 없다.
- 한 상품을 구매해도 다른 상품의 조회 기록은 초기화하지 않는다.
- 확률의 상승·하락을 인위적으로 만들지 않는다. 실제 모델 결과를 그대로 사용한다.

## 2. 데이터 사용 기준

| 이벤트 | v1에서의 용도 |
| --- | --- |
| `view` | 모델 입력, 후보 상품 추가, 확률 갱신 |
| `addtocart` | v1 입력에서 제외. 나중에 별도 비교 실험에 사용 |
| `transaction` | 구매 정답(GT) 생성에 사용. 모델 입력에 포함하지 않음 |

`view=1`, `addtocart=3`, `transaction=5`처럼 행동에 임의의 점수를 부여하지 않는다. 특히 `transaction`은 예측하려는 정답이므로 입력 점수에 섞지 않는다.

현재 RetailRocket `events.csv`에는 조회 약 266만 건, 장바구니 추가 약 6.9만 건, 구매 약 2.2만 건이 있다. 첫 조회를 기준으로 확인한 사용자·상품 쌍 약 213만 개 중 약 1.9만 개에서 이후 같은 상품의 구매가 관찰됐다. 구매 사례가 드물다는 점을 모델 학습과 평가에 반영해야 한다.

## 3. 예측 시점과 후보 상품

1. 사용자의 `view` 기록을 시간순으로 처리한다.
2. 조회가 발생하면 그 시점까지 사용자가 조회한 모든 상품을 후보로 둔다.
3. 후보 상품 각각에 대해 그 시점까지의 조회 행동만으로 피처를 계산한다.
4. 모든 후보 상품의 구매 확률을 다시 계산한다.
5. 이미 구매한 상품은 `구매 완료`로 표시하고 이후 첫 구매 예측 대상에서 제외한다. 다른 상품의 예측은 계속한다.

조회 사이에 공백이 있다는 이유로 사용자의 기록을 초기화하지 않는다. 오래된 조회의 영향은 마지막 조회 후 경과 시간 등의 피처로 표현한다.

같은 시각에 조회와 구매가 함께 기록돼 선후 관계를 알 수 없다면, 그 예측 시점은 학습·평가에서 제외하고 제외 건수를 기록한다.

## 4. 정답(GT) 정의

예측 시점 `t`의 후보 상품에 대해 다음과 같이 정답을 만든다.

- **정답 1:** `t` 이후 같은 사용자·같은 상품의 `transaction`이 기록됨
- **정답 0:** 데이터가 끝날 때까지 같은 사용자·같은 상품의 `transaction`이 기록되지 않음

다른 상품을 구매했다는 이유로 해당 후보의 정답을 1로 바꾸지 않는다. 여러 후보 상품을 구매했다면 각각 정답 1이다.

구매 확인에 30분·24시간 같은 고정된 시간 제한을 두지 않는다. 다만 데이터는 유한하므로, 정답 0은 **“기록된 미래에 구매가 관찰되지 않았다”**는 뜻이다. “영원히 구매하지 않는다”는 뜻으로 해석하지 않는다.

## 5. 첫 모델의 입력 피처

첫 모델은 `view`에서 계산할 수 있는 피처로 시작한다.

| 피처 | 의미 |
| --- | --- |
| 해당 상품 조회 횟수 | 상품을 반복해서 본 정도 |
| 해당 상품 조회 비중 | 사용자의 전체 조회 중 그 상품이 차지하는 비율 |
| 첫 조회 후 경과 시간 | 처음 관심을 보인 뒤 흐른 시간 |
| 마지막 조회 후 경과 시간 | 최근에 그 상품을 봤는지 |
| 다른 상품 조회 후 재방문 횟수 | 비교하다가 해당 상품으로 돌아온 행동 |
| 사용자 전체 조회 횟수 | 현재까지 관찰된 행동량 |
| 조회한 서로 다른 상품 수 | 비교 중인 후보의 수 |
| 가장 최근에 조회한 상품 여부 | 현재 관심이 향한 상품인지 |

이벤트 사이의 시간 차이를 **실제 페이지 체류 시간**이라고 부르지 않는다. 구매 결과나 예측 시점 이후의 조회도 피처에 포함하지 않는다. 학습과 서비스에서 동일한 방식으로 피처를 계산한다.

## 6. 모델 학습

1. 각 조회 시점에 대해 후보 상품별 학습 행을 만든다.
2. 같은 사용자의 기록이 학습·검증·확률 보정·최종 평가에 섞이지 않도록 분리한다.
3. 단순 구매 비율과 로지스틱 회귀를 기준선으로 평가한다.
4. LightGBM 이진 분류 모델을 학습하고 검증 데이터로 선택한다.
5. 별도 데이터에서 모델 점수를 확률로 보정한다.
6. 검증 결과를 바탕으로 `구매 예상` 판정에 사용할 임계값을 정한다.
7. 모델과 임계값을 확정한 뒤 최종 평가 데이터를 평가한다.

임계값을 무조건 50%로 정하지 않는다. 보기 좋은 화면을 만들기 위해 모델 점수를 임의로 60%나 90%로 바꾸지 않는다.

## 7. 데이터 전처리 원칙

- 결측치, 중복 행, 이벤트 순서와 사용자별 조회량을 확인한다.
- 과다 조회 사용자는 먼저 이상 행동으로 표시하고, 포함했을 때와 제외했을 때의 결과를 비교한다. 조회 수만으로 일괄 삭제하지 않는다.
- 조회가 한 건뿐인 사용자도 유지한다. 첫 조회 직후의 예측은 실제 체험에 필요한 상황이다.
- 학습 속도를 위해 데이터를 샘플링한다면 샘플링 방법과 비율을 기록한다. 최종 평가에는 실제 구매 비율을 유지한다.
- 같은 구매가 여러 이전 조회 시점의 정답으로 반복될 수 있으므로, 행 단위 결과와 사용자·상품 단위 결과를 함께 확인한다.

## 8. 평가 기준

| 평가 관점 | 확인할 내용 |
| --- | --- |
| 상품별 구매 구분 | AP(PR-AUC), 정밀도, 재현율, F1 |
| 확률의 정확성 | Log loss, Brier score, 예측 확률 구간별 실제 구매 비율 |
| 여러 후보가 있는 상황 | 후보가 2개 이상일 때의 상품별 판정과 순위 |
| 행동 기록의 길이 | 첫 조회 사용자와 반복 조회 사용자를 나눠 평가 |
| 데이터 종료 영향 | 예측 날짜에 따라 관찰 가능한 미래가 달라지는지 확인 |
| 확률 변화 | 상품 A 조회 → B 조회 → A 재조회 등의 기록에서 각 상품의 확률 변화를 확인 |

구매 사례가 드물기 때문에 전체 정확도만으로 모델을 평가하지 않는다. 기존 30분·24시간 실험의 성능은 이 모델의 성능으로 사용하지 않는다.

## 9. 서비스 출력

조회가 발생할 때마다, 현재 후보 상품마다 다음 정보를 출력한다.

| 출력 항목 | 설명 |
| --- | --- |
| 상품 ID | 예측 대상 상품 |
| 구매 예측 확률 | 보정된 모델 확률. 화면에는 퍼센트로 표시 가능 |
| 구매 판정 | 임계값에 따른 `구매 예상` 또는 `미구매 예상` |
| 상태 | 예측 대상 또는 `구매 완료` |

예를 들어 화면에서 상품 A와 B의 확률을 각각 보여주는 형태다. `A 90%`, `B 20%` 같은 숫자는 설명용 예시일 뿐 실제 모델이 그런 값을 낸다는 뜻은 아니다. `구매 미정`은 현재 정한 이진 판정에 포함하지 않는다.

## 10. 진행 순서와 얻는 결과

| 단계 | 작업 | 얻는 결과 |
| --- | --- | --- |
| 1 | 조회 시점별·상품별 학습 데이터 생성 | 피처와 구매 정답이 담긴 데이터 |
| 2 | 기준선과 LightGBM 학습 | 상품별 구매 점수를 내는 모델 |
| 3 | 확률 보정과 최종 평가 | 확률의 신뢰도와 구매 판정 성능을 보여주는 보고서 |
| 4 | 조회 이벤트마다 모든 후보를 다시 예측하도록 서비스 연결 | 행동에 따라 갱신되는 상품별 확률 화면 |
| 5 | `addtocart` 포함 모델을 별도 실험으로 학습 | 조회 전용 모델과의 성능·체험 차이 비교 |

## 11. 해석상 주의할 점

이 모델은 **현재까지의 조회 행동을 바탕으로, 기록된 미래에 해당 상품의 구매가 나타날 가능성**을 학습한다. 구매 확률이 실제로 얼마나 정확한지, 조회만으로 눈에 띄는 확률 변화가 나타나는지는 새 모델의 평가 결과로 확인해야 한다.

데이터에 명시적인 쇼핑 종료 기록이 없으므로 `미구매 예상`을 “이번 쇼핑에서 절대 사지 않음”이나 “평생 구매하지 않음”으로 설명하지 않는다.
